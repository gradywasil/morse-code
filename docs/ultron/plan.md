# Build Plan — The Morse Code Broadcaster

Source of truth: `docs/ultron/town-hall.md` (approved scope) · `docs/ultron/design-brief.md` (locked world: The Register) · `PRODUCT.md` (stack: plain static, no build step, no dependencies).
Status legend: pending → in-progress → awaiting-approval → completed. The task index below is authoritative; `state.md` tracks phase cursor; `production-log.md` collects validation evidence.

## Fixed by scope (not re-decided here)

- Plain static HTML/CSS/JS; ES modules; no build step, no dependencies; Node built-in test runner (`node --test`).
- Broadcast-only; one-shot + replay; full ITU map (A–Z, 0–9, punctuation), no prosigns; standard (PARIS) timing, dot = 1200/WPM ms; ratios 1/3/1/3/7.
- Channels: torch (Chromium-based Android browsers and iOS Safari 17.4+; screen fallback everywhere else) / screen-flash (everywhere, first-class) / audio tones; synced on-screen tape readout.
- Privacy: no video-frame APIs ever; camera track released after broadcast; HTTPS-only delivery.
- Photosafety: notice before first broadcast; default speed keeps sustained-dot flashing under 3 Hz; capped upper speed; `prefers-reduced-motion` honored.
- Design world: "The Register" (code-led). Direction contract comment in `index.html` body-first; DESIGN.md written at finish.

## Planning-owned decisions (made here; refine, don't re-litigate)

- **Speed steps (committed per R2, 2026-08-28):** LEARNER 5 WPM (default — sustained dots ≈2.1 Hz, under the 3 Hz general-flash threshold), STANDARD 8, BRISK 12; **hard cap 12 WPM** (lowered from 15 per R2: at 15 WPM jitter ≈41% of a dot and sustained dots ≈6.25 Hz; 12 WPM matches the naval visual-signalling ceiling). BRISK carries a rapid-flash caution line in U1 copy (sustained dots ≈5 Hz, above the 3 Hz threshold — opt-in behind the hazard plate). Named steps, never a continuous slider (Cape's named-states law).
- **URL hash format:** `#m=<base64url(UTF-8 message)>&s=<step id>`. Parse on load (auto-fill), update via `replaceState`, share button copies full URL. No server.
- **Copy pack drafted in U1** (why-camera, denied, unsupported-positive, hazard plate, standby/caution/GO lines) — final wording locked in U1 review, not per-task.

**F3 — Torch channel** · frontend · medium · `completed`
- Outcome: `js/torch.js` — detection per R1 order: (1) guarded capability check (`track.getCapabilities?.().torch` — guard the function itself, Firefox history); (2) trial `applyConstraints` probe of BOTH `torch:true` AND `torch:false` (advanced form `advanced:[{torch}]` with top-level `{torch}` fallback; ~1.5 s timeout on each; any rejection/timeout → `track.stop()` + screen mode); (3) screen fallback.
